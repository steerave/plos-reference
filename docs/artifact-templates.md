# Artifact Templates

Reference document. End-state shapes for the three compiled artifacts and representative Dataview dashboards. These templates are what compile passes write toward and what hand-written dashboards follow.

Two surfaces, two shapes. Compiled artifacts are full markdown documents written by Claude Code on a schedule. Dataview dashboards are markdown files holding query blocks rendered live in Obsidian.

This doc shows:

- **Three compiled artifact templates** — one per compiled artifact: `this-week.md`, `anomalies.md`, `tax-prep.md`.
- **Two representative Dataview dashboard templates** — `upcoming.md` and `properties.md`. The other 8 dashboards follow the same shape conventions; once these two are clear, the rest are mechanical.

---

## Conventions for compiled artifacts

- **YAML frontmatter** with refresh timestamp, sources read, compile pass version.
- **Refresh timestamp** prominently visible so staleness is obvious.
- **Source provenance inline** — every claim cites the source path it came from with `→ /source/...`.
- **Stable section structure** run-over-run.
- **Footer line** identifying the compile pass and how to regenerate.

## Conventions for Dataview dashboards

- **YAML frontmatter** marking it as a dashboard, listing source folders queried.
- **Each query in its own labeled section** with a brief description of what it returns.
- **Frontmatter on source files is the contract** — dashboards are only as good as the frontmatter they read.
- **No synthesis prose** in dashboard pages; that's compiled-artifact territory.

## Dataview template 1 — `dashboards/upcoming.md` (cross-domain date aggregation)

````markdown
---
type: dashboard
dashboard: upcoming
sources_queried:
  - source/properties
  - source/vehicles
  - source/accounts
  - source/people
---

# Upcoming — Next 30 / 60 / 90 Days

This page renders live in Obsidian. Dates pulled from frontmatter across all source entities.

## Next 30 days

```dataview
TABLE
  type as "Type",
  insurance_renewal as "Insurance",
  registration_expiry as "Registration",
  policy_renewal as "Policy"
FROM "source"
WHERE (insurance_renewal <= date(today) + dur(30 days))
   OR (registration_expiry <= date(today) + dur(30 days))
   OR (policy_renewal <= date(today) + dur(30 days))
SORT insurance_renewal ASC
```

## Next 31–60 days

```dataview
TABLE
  type as "Type",
  insurance_renewal as "Insurance",
  registration_expiry as "Registration"
FROM "source"
WHERE (insurance_renewal > date(today) + dur(30 days)
       AND insurance_renewal <= date(today) + dur(60 days))
   OR (registration_expiry > date(today) + dur(30 days)
       AND registration_expiry <= date(today) + dur(60 days))
SORT insurance_renewal ASC
```

## Next 61–90 days

```dataview
TABLE
  type as "Type",
  insurance_renewal as "Insurance",
  registration_expiry as "Registration"
FROM "source"
WHERE (insurance_renewal > date(today) + dur(60 days)
       AND insurance_renewal <= date(today) + dur(90 days))
SORT insurance_renewal ASC
```

## Birthdays and anniversaries — next 90 days

```dataview
TABLE
  birthday as "Date",
  relation as "Relation"
FROM "source/people"
WHERE birthday >= date(today)
  AND birthday <= date(today) + dur(90 days)
SORT birthday ASC
```
````

## Dataview template 2 — `dashboards/properties.md` (per-entity snapshot)

````markdown
---
type: dashboard
dashboard: properties
sources_queried:
  - source/properties
---

# Properties Dashboard

Live view of every active property. Edit any property's `index.md` and the table below updates next time you open this page.

## Active properties

```dataview
TABLE
  address as "Address",
  purpose as "Use",
  mortgage_servicer_current as "Servicer",
  insurance_carrier_current as "Carrier",
  insurance_renewal as "Renews",
  hoa as "HOA"
FROM "source/properties"
WHERE status = "active"
SORT purpose, address
```

## Carrying cost — monthly, per property

```dataview
TABLE WITHOUT ID
  file.link as "Property",
  monthly_pi as "P&I",
  monthly_taxes_escrowed as "Taxes",
  monthly_insurance as "Insurance",
  monthly_hoa as "HOA",
  monthly_utilities_avg as "Utilities (avg)",
  (monthly_pi + monthly_taxes_escrowed + monthly_insurance + monthly_hoa + monthly_utilities_avg) as "Total"
FROM "source/properties"
WHERE status = "active"
SORT (monthly_pi + monthly_taxes_escrowed + monthly_insurance + monthly_hoa + monthly_utilities_avg) DESC
```

## Cash flow — rentals only

```dataview
TABLE WITHOUT ID
  file.link as "Property",
  monthly_rent as "Rent",
  (monthly_pi + monthly_taxes_escrowed + monthly_insurance + monthly_hoa + monthly_utilities_avg) as "Cost",
  (monthly_rent - (monthly_pi + monthly_taxes_escrowed + monthly_insurance + monthly_hoa + monthly_utilities_avg)) as "Net"
FROM "source/properties"
WHERE purpose = "rental" AND status = "active"
SORT (monthly_rent - (monthly_pi + monthly_taxes_escrowed + monthly_insurance + monthly_hoa + monthly_utilities_avg)) DESC
```

## Insurance coverage detail

```dataview
TABLE
  insurance_carrier_current as "Carrier",
  insurance_policy_number as "Policy #",
  insurance_premium_annual as "Annual Premium",
  insurance_dwelling_coverage as "Dwelling",
  insurance_liability_coverage as "Liability"
FROM "source/properties"
WHERE status = "active"
```
````

## Notes on the templates

**Frontmatter on source files is the contract that makes Dataview work.** If `monthly_pi` isn't in every property's frontmatter, the carrying-cost query produces blanks. The discipline of consistent frontmatter is enforced via `CONVENTIONS.md` and applied in the source layer's `index.md` shapes.

**Compiled artifacts CAN read Dataview dashboard pages.** When `this-week.md` synthesizes "what needs your attention," it can pull from the same frontmatter the upcoming dashboard queries — but at compile time, with reasoning over the result. Dashboards and compiled artifacts share the same source layer.

**The other 8 dashboards follow the same shape.** `cash-flow.md` is per-month grouped sums of transactions. `subscriptions.md` is a list with sum. `medical.md` is per-person tables. `vehicles.md` mirrors `properties.md` in structure. Once frontmatter on the source records is right, each dashboard is an hour or two of writing the right Dataview queries.

**Dataview dashboards are version-controlled markdown.** They live in git alongside everything else. The query is the document; the result is rendered live by Obsidian.
